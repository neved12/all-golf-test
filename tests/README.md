# ALL:GOLF 테스트

브라우저 없이 앱 코드를 그대로 실행하는 회귀 테스트와, 실제 화면을 점검하는 도구가 있습니다.

## 1. 시나리오 회귀 테스트

```bash
node tests/run-scenarios.js
```

- `tests/dom-shim.js` 가 최소 DOM(localStorage, window 이벤트, 타이머)을 만들고,
  `data/*.js` · `app.js` · `tests/scenarios.js` 를 한 스크립트로 이어 붙여 **실제 앱 코드**를 실행합니다.
- 검증 항목
  - 데이터 보존: 전국 골프장 목록, 기존 저장 키(`allGolfReservations`, `allGolfOperationsV1`), 정보 전용 골프장의 가상 티타임 미생성
  - 4인 예약: 그린피 합계, 카트·캐디, 예약금, 현장 결제, 재고 차감, 예약 번호
  - 3인 추가금: 1인 추가금 포함 금액, 팀 총액
  - 특가 예약: 특가 가격 적용, 할인 금액, 총액
  - 취소 후 대기 알림: 예약 취소 → 재고 복구 → 대기자 알림 생성 → 알림함/대기 화면 노출
  - 연락처: 자동 하이픈, 형식 검증, 잘못된 번호 예약 차단
  - 일정 저장(.ics)과 공유 링크
  - 재방문: 찜, 날짜 연동 티타임, 최근 검색, 최근 본 골프장
  - 예약 상세: 예약번호, 요금 내역, 3인 추가금, 취소 기한, 환불 예상, 날짜 기준 지난 예약 분류
  - 준비 중 메뉴(조인·레슨·여행)와 샘플 쿠폰 구분
  - 5단계 제휴: 신청 접수·검증(연락처/이메일/중복), 접수번호 형식, 상태 조회, 관리자 승인·반려(사유 필수),
    승인 후 사용자 앱 예약 가능 전환·신규 골프장 등록·실제 예약 완료, 시연 백업에 제휴 신청 키 포함 및 개인정보 제외
- 현재 120개 항목을 검사합니다. 실패가 있으면 종료 코드 1을 돌려줍니다.

## 2. 6단계 서버·DB 테스트

```bash
node tests/run-server-scenarios.js
```

- `server/index.js` 를 **임시 DB 파일**로 실제 기동하고 HTTP API 를 검사합니다(90개).
- 서로 다른 컨텍스트 시뮬레이션
  - A(골프장): 제휴 신청 접수 → 접수번호·조회 코드 발급 → 본인 조회
  - B(본사): 관리자 로그인 → 목록 확인 → 승인 → 처리 이력 확인
  - C(사용자 앱): 승인된 골프장이 앱에서 `bookable` 로 표시되고 시연 티타임 예약이 되는지 실제 앱 코드로 확인
- 인증 없는 승인·반려(401), 위조 토큰(401), 타인 신청 조회(403), 중복 신청·중복 승인(409),
  10건 동시 승인 중 1건만 성공하는 경쟁 상태 방어, 서버 재시작 후 데이터 보존을 검사합니다.
- 서버가 없는 정적 호스팅에서는 `data/api-client.js` 가 **네트워크 요청 0건**으로 정적 모드로
  폴백하는지, 설정된 서버가 꺼져 있을 때도 예외 없이 정적 모드가 되는지 확인합니다.

## 3. 7단계 계정·권한·운영 테스트

```bash
node tests/run-stage7-scenarios.js
```

- 실제 서버를 임시 DB로 기동해 두 골프장(A/B)을 승인하고 담당자 계정을 발급한 뒤 HTTP API 를 검사합니다(187개).
- 검사 항목
  - 계정 발급·중복 이메일·약한 비밀번호·제휴 승인 안된 골프장 차단, 비밀번호 해시 비노출
  - 담당자 로그인/세션, 본사 토큰과 담당자 토큰 교차 사용 차단
  - A의 티타임 등록·검증(날짜/시간/부/팀/인원/가격), 중복 409, B 데이터 조회·수정·삭제·명의 등록 403
  - version 기반 수정 충돌 409, 요금 3인·4인 그룹 계산, 특가 할인율·기간 겹침 409
  - 공개 카탈로그의 서버 티타임·특가·재고 연동 표시(8단계에서 true 로 전환), 기존 시연 티타임 폴백
  - 계정 비활성화·재개·비밀번호 재설정 시 기존 세션 즉시 무효화(401)
  - 서버 재시작 후 계정·티타임·요금·특가 유지, 예약/특가 연결 티타임 삭제 차단
  - 정적 모드 네트워크 요청 0건, 고객 앱의 서버 티타임·특가·3인 추가금 반영

## 3-1. 8단계 예약 엔진 테스트

```bash
node tests/run-stage8-scenarios.js
```

- 실제 서버를 임시 DB로 기동해(임시 Hold TTL 3초) 예약 엔진 전체를 검사합니다(168개).
- 검사 항목
  - health 8단계 이상·DB 스키마 3 이상·예약/Hold 기능 플래그, 고객 앱에 예약 클라이언트 포함
  - Hold 생성/재사용/세션당 3건 한도/마지막 1팀 다른 세션 409/해제·만료 시 재고 복구
  - 예약 확정 시 원자적 재고 차감, 예약번호 `AG-YYMMDD-NNNNN`, 금액·예약금 계산, 입력 검증(인원·연락처·이름·티타임 불일치)
  - **동시 예약 3건 중 1팀 티타임은 1건만 성공, 나머지 409**(Overbooking 방어)
  - **멱등 키 재전송은 이중 차감 없이 동일 예약 반환**
  - 예약번호+연락처 조회(다른 연락처 403, 없는 예약 404), 취소·환불률·수수료·재고 복구, 재취소 멱등
  - 취소 가능 기한 초과 409, 담당자 강제 취소, 이용 완료·노쇼 상태 전이
  - 담당자 골프장 격리(타 골프장 목록·상세·상태 변경 403), 본사 전체 조회·취소·사유 필수·환불 계산
  - 감사 로그(예약 확정·취소·상태 변경), 운영 현황 예약 집계
  - 서버 재시작 후 예약·재고 유지, 기존 DB(v2) → v4 자동 호환

## 3-2. 9단계 운영 자동화 테스트

```bash
node tests/run-stage9-scenarios.js
```

- 실제 서버를 임시 DB로 기동해 본사 운영 통계·수수료·정산·알림 로그를 검사합니다(200개).
- 검사 항목
  - health 9단계·DB 스키마 v4·통계/정산/수수료/알림 플래그, 기본 수수료율 8%·범위 0~30
  - 수수료율 기본값·변경·범위 초과 400·이전 버전 409·없는 골프장 404·담당자 본인/타 골프장 403
  - 운영 통계(오늘/7일/30일/전체) 예약 건수·GMV·취소·환불·노쇼율·1/2/3부·객단가·정산 기준액 정확값
  - 예약 접수일 기준 기간 필터(45일 전 접수 건은 오늘/30일 제외, 전체 포함)
  - 통계 CSV(UTF-8 BOM·Content-Disposition·행 수)·인증 401
  - 정산서 계산(GMV+취소 수수료, 수수료율 반영)·같은/겹치는 기간 409·역순/누락 기간 400
  - DRAFT→PENDING→CONFIRMED→PAID 전이·건너뛰기/역행/중복 전이 409·버전 충돌 409·상태 이력·감사 로그
  - 수수료율 변경 후 기존 정산서 스냅샷 유지·새 정산서에 새 율 적용
  - 담당자 정산·알림 골프장 격리(목록·상세·조회 403), 담당자 생성/전이 403
  - 알림 시뮬레이션 로그 16건(예약 6×2 + 취소 2 + 정산 2)·상태 simulated·연락처 마스킹·이벤트/골프장 필터
  - 서버 재시작 후 정산 상태·수수료율·알림 유지, 기존 DB(v3) → v4 자동 승격
  - 정적 모드 API 요청 0건
  - 정적 모드 예약 모듈 요청 0건, 고객 앱이 서버 잔여를 그대로 사용(로컬 중복 차감 없음)

## 4. 화면 스크립트 스모크 (partner/admin/demo)

```bash
node tests/run-ui-smoke.js
```

- 원격 환경에서 `127.0.0.1` 실브라우저 E2E 가 막혀 있어, `partner/partner.js` · `admin/admin.js` · `demo/demo.js` 를
  최소 DOM 으로 실행하고 클릭 핸들러를 직접 호출해 실제 서버에 붙여 확인합니다.
  (92개 = 골프장 관리자 23 + 본사 관리자 28 + 10단계 허브 서버 모드 32 + 정적 모드 9 + 10단계 허브 정적 5)
- 골프장 관리자: 로그인 → 운영 현황 → 티타임 추가(서버 저장·목록 표시) → 요금 저장
  → 예약 관리(서버 예약 표시·통계) → 예약 취소(재고 복구 확인)
  → 정산 내역(정산서·수수료율) → 알림 로그(시연 기록) → 로그아웃
- 본사 관리자: 로그인 → 제휴 계정 관리·계정 생성(초기 비밀번호 1회 표시) → 운영 현황
  → 전체 예약(목록·상세 모달) → 감사 로그(예약 확정·취소 포함)
  → 운영 통계(GMV·노쇼율·제휴 승인 전환율·기간 전환) → 정산·수수료(수수료율 저장·정산서 생성·DRAFT→PENDING 전이)
- 10단계 시연 허브: 렌더·509/68/441·투자자 7단계·체크리스트 진행률·제휴 6단계·시뮬레이터 계산·복사
  → 안전 가드(문구·체크 없이는 실행 불가) → 관리자 확인 → 시연 데이터 준비(84건) → 초기화(시연 0건, 일반 데이터 유지)
- 정적 모드: 서버 없이 admin 화면을 띄워 9단계 페이지가 안내 문구만 표시하고 API 요청 0건인지 확인,
  10단계 허브도 정적 모드에서 렌더되고 API 요청 0건인지 확인
- 10단계 시나리오는 아래 명령으로 따로 실행합니다: `node tests/run-stage10-scenarios.js` (113개)
- 실제 브라우저 렌더링·CSS·모바일 레이아웃까지 검증하는 것은 아니므로, 그 범위는 별도로 표시합니다.
