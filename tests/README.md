# ALL:GOLF 테스트

브라우저 없이 앱 코드를 그대로 실행하는 회귀 테스트와, 실제 화면을 점검하는 도구가 있습니다.

## 1. 시나리오 회귀 테스트

```bash
node tests/run-scenarios.js
```

- `tests/dom-shim.js` 가 최소 DOM(localStorage, window 이벤트, 타이머)을 만들고,
  `data/*.js` · `app.js` · `tests/scenarios.js` 를 한 스크립트로 이어 붙여 **실제 앱 코드**를 실행합니다.
- 검증 항목
  - 데이터 보존: 전국 골프장 목록, 기존 저장 키(`allGolfReservations`, `allGolfOperationsV1`), 정보 전용 골프장의 가상 티타임 미생성
  - 4인 예약: 그린피 합계, 카트·캐디, 예약금, 현장 결제, 재고 차감, 예약 번호
  - 3인 추가금: 1인 추가금 포함 금액, 팀 총액
  - 특가 예약: 특가 가격 적용, 할인 금액, 총액
  - 취소 후 대기 알림: 예약 취소 → 재고 복구 → 대기자 알림 생성 → 알림함/대기 화면 노출
  - 연락처: 자동 하이픈, 형식 검증, 잘못된 번호 예약 차단
  - 일정 저장(.ics)과 공유 링크
  - 재방문: 찜, 날짜 연동 티타임, 최근 검색, 최근 본 골프장
  - 예약 상세: 예약번호, 요금 내역, 3인 추가금, 취소 기한, 환불 예상, 날짜 기준 지난 예약 분류
  - 준비 중 메뉴(조인·레슨·여행)와 샘플 쿠폰 구분
  - 5단계 제휴: 신청 접수·검증(연락처/이메일/중복), 접수번호 형식, 상태 조회, 관리자 승인·반려(사유 필수),
    승인 후 사용자 앱 예약 가능 전환·신규 골프장 등록·실제 예약 완료, 시연 백업에 제휴 신청 키 포함 및 개인정보 제외
- 현재 120개 항목을 검사합니다. 실패가 있으면 종료 코드 1을 돌려줍니다.

## 2. 6단계 서버·DB 테스트

```bash
node tests/run-server-scenarios.js
```

- `server/index.js` 를 **임시 DB 파일**로 실제 기동하고 HTTP API 를 검사합니다(90개).
- 서로 다른 컨텍스트 시뮬레이션
  - A(골프장): 제휴 신청 접수 → 접수번호·조회 코드 발급 → 본인 조회
  - B(본사): 관리자 로그인 → 목록 확인 → 승인 → 처리 이력 확인
  - C(사용자 앱): 승인된 골프장이 앱에서 `bookable` 로 표시되고 시연 티타임 예약이 되는지 실제 앱 코드로 확인
- 인증 없는 승인·반려(401), 위조 토큰(401), 타인 신청 조회(403), 중복 신청·중복 승인(409),
  10건 동시 승인 중 1건만 성공하는 경쟁 상태 방어, 서버 재시작 후 데이터 보존을 검사합니다.
- 서버가 없는 정적 호스팅에서는 `data/api-client.js` 가 **네트워크 요청 0건**으로 정적 모드로
  폴백하는지, 설정된 서버가 꺼져 있을 때도 예외 없이 정적 모드가 되는지 확인합니다.

## 3. 7단계 계정·권한·운영 테스트

```bash
node tests/run-stage7-scenarios.js
```

- 실제 서버를 임시 DB로 기동해 두 골프장(A/B)을 승인하고 담당자 계정을 발급한 뒤 HTTP API 를 검사합니다(187개).
- 검사 항목
  - 계정 발급·중복 이메일·약한 비밀번호·제휴 승인 안된 골프장 차단, 비밀번호 해시 비노출
  - 담당자 로그인/세션, 본사 토큰과 담당자 토큰 교차 사용 차단
  - A의 티타임 등록·검증(날짜/시간/부/팀/인원/가격), 중복 409, B 데이터 조회·수정·삭제·명의 등록 403
  - version 기반 수정 충돌 409, 요금 3인·4인 그룹 계산, 특가 할인율·기간 겹침 409
  - 공개 카탈로그의 서버 티타임·특가·재고 미연동 표시, 기존 시연 티타임 폴백
  - 계정 비활성화·재개·비밀번호 재설정 시 기존 세션 즉시 무효화(401)
  - 서버 재시작 후 계정·티타임·요금·특가 유지, 예약/특가 연결 티타임 삭제 차단
  - 정적 모드 네트워크 요청 0건, 고객 앱의 서버 티타임·특가·3인 추가금 반영

## 4. 화면 스크립트 스모크 (partner/admin)

```bash
node tests/run-ui-smoke.js
```

- 원격 환경에서 `127.0.0.1` 실브라우저 E2E 가 막혀 있어, `partner/partner.js` · `admin/admin.js` 를
  최소 DOM 으로 실행하고 클릭 핸들러를 직접 호출해 실제 서버에 붙여 확인합니다(22개).
- 골프장 관리자: 로그인 → 운영 현황 → 티타임 추가(서버 저장·목록 표시) → 요금 저장 → 로그아웃
- 본사 관리자: 로그인 → 제휴 계정 관리·계정 생성(초기 비밀번호 1회 표시) → 운영 현황 → 감사 로그
- 실제 브라우저 렌더링·CSS·모바일 레이아웃까지 검증하는 것은 아니므로, 그 범위는 별도로 표시합니다.

## 5. 로컬 서버

```bash
npm start                   # http://127.0.0.1:4173/  (7단계 서버: API + 정적)
PORT=8080 npm start
node dev-server.js          # API 없는 정적 전용 서버(참고용)
```

- 사용자 앱 `/` · 본사 관리자 `/admin/` · 골프장 관리자 `/partner/`
